# Changelog

## zupmxode 0.0.0.9000

- Initial CRAN submission.

- [`pmx_ode_tier()`](https://pedrobtz.github.io/zupmxode/reference/pmx_ode_tier.md)
  reports and sets the tier a model runs on: native code generated by
  MIR, or MIR’s interpreter.

- [`pmx_ode_model()`](https://pedrobtz.github.io/zupmxode/reference/pmx_ode_model.md)
  compiles a model written in the subset of rxode2’s model language
  described in its documentation, including `linCmt()`.

- [`pmx_ode_events()`](https://pedrobtz.github.io/zupmxode/reference/pmx_ode_events.md)
  builds a NONMEM-style event table of doses and observation times.

- [`pmx_ode_solve()`](https://pedrobtz.github.io/zupmxode/reference/pmx_ode_solve.md)
  solves closed-form models (`linCmt()`) for one or more subjects,
  exactly, with time-varying covariates, resets and steady state.

- [`pmx_ode_solve()`](https://pedrobtz.github.io/zupmxode/reference/pmx_ode_solve.md)
  solves models with no closed form, with LSODA (from the bundled
  liblsoda) or Dormand-Prince 5(4).

- Linear models are solved exactly between events by the matrix
  exponential.

- [`pmx_ode_method()`](https://pedrobtz.github.io/zupmxode/reference/pmx_ode_method.md)
  reports and sets a model’s solver;
  [`pmx_ode_info()`](https://pedrobtz.github.io/zupmxode/reference/pmx_ode_info.md)
  says what a model is, which solver it takes and why, its tier and how
  long it took to compile.

- Subjects are solved in parallel with OpenMP;
  [`pmx_ode_threads()`](https://pedrobtz.github.io/zupmxode/reference/pmx_ode_threads.md)
  sets how many threads, one by default. Results are the same, bit for
  bit, at any thread count.

- [`pmx_ode_tier()`](https://pedrobtz.github.io/zupmxode/reference/pmx_ode_tier.md)
  keeps a model’s compartments, outputs and solver when it makes the
  copy on another tier.
